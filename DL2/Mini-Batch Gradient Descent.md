# Mini-Batch 梯度下降法 (Mini-Batch Gradient Descent) 完整課程筆記

---

## 1. 為什麼需要 Mini-Batch 梯度下降？

### 1.1 深度學習的挑戰
- **經驗與迭代驅動**：應用機器學習是一個高度經驗化與直覺化的過程，通常需要訓練大量模型才能找到最合適的架構與超參數。
- **大數據依賴**：深度學習在龐大數據集（Big Data）上表現最佳，但在大型數據集上訓練非常耗時。
- **效率需求**：擁有快速且高效的優化演算法能極大地提升研發與迭代效率。

### 1.2 傳統 Batch 梯度下降的瓶頸
- **向量化（Vectorization）的極限**：雖然向量化可以避免顯式的 `for` 迴圈並提升計算效率，但當樣本總數 $M$ 非常龐大（例如 5,000,000 或 50,000,000）時，單次矩陣運算依然會變得極為緩慢。
- **高昂的等待成本**：Batch 梯度下降（Batch Gradient Descent）每次更新參數前，都必須處理完**整個**訓練集（全部 $M$ 個樣本）。這意味著每前進一小步，都需要消耗極大的計算資源與等待時間。

### 1.3 Mini-Batch 的解決方案
- **核心思想**：如果能在處理完整個龐大數據集之前，就讓梯度下降演算法開始取得進展，將會大大加快訓練速度。
- **作法**：將巨大訓練集拆分成較小的「小批次訓練集」（稱為 Mini-Batches），在每個 Mini-Batch 上即時進行參數更新。

## 2. 數據拆分與符號表示 (Notation)

假設我們有 $M = 5,000,000$ 個訓練樣本，決定將其拆分為每個 mini-batch 包含 $1,000$ 個樣本：

### 2.1 拆分方式
- **輸入矩陣拆分**：將輸入矩陣 $X$（維度為 $n_x 	imes M$）拆分為：
  $$X^{\{1\}}, X^{\{2\}}, \dots, X^{\{5000\}}$$
  - $X^{\{1\}}$ 包含第 $1$ 到 $1000$ 個樣本。
  - $X^{\{2\}}$ 包含第 $1001$ 到 $2000$ 個樣本，以此類推。
- **標籤向量拆分**：將標籤向量 $Y$（維度為 $1 	imes M$）對應拆分為：
  $$Y^{\{1\}}, Y^{\{2\}}, \dots, Y^{\{5000\}}$$

### 2.2 維度說明
- 每個 $X^{\{t\}}$ 的維度均為 $n_x 	imes 1000$。
- 每個 $Y^{\{t\}}$ 的維度均為 $1 	imes 1000$。

### 2.3 符號區分總結
| 符號標記 | 語義說明 | 範例與維度 |
| :--- | :--- | :--- |
| $x^{(i)}$ | 代表第 $i$ 個訓練樣本（使用圓括號上標） | $x^{(1)}, x^{(2)}$ |
| $z^{[l]}$ | 代表神經網路第 $l$ 層的參數/數值（使用中括號上標） | $z^{[1]}, A^{[2]}$ |
| $X^{\{t\}}, Y^{\{t\}}$ | 代表第 $t$ 個 Mini-Batch（使用花括號上標） | $X^{\{1\}}$ 維度: $n_x 	imes 1000$ |

## 3. Mini-Batch 梯度下降演算法流程

在 Mini-Batch 梯度下降法中，我們會執行以下步驟：

### 3.1 演算法流程與步驟
1. **外層迴圈**：針對 $t = 1$ 到 $5000$（假設有 $5000$ 個 mini-batches）：
   - 在迴圈內部，僅使用當前的 $X^{\{t\}}$ 和 $Y^{\{t\}}$ 執行一步梯度下降更新。這就像是在一個大小僅有 $M = 1000$ 的小型訓練集上運行標準的梯度下降法。

2. **前向傳播 (Forward Propagation)**：
   - $Z^{[1]} = W^{[1]} X^{\{t\}} + b^{[1]}$
   - $A^{[1]} = g^{[1]}(Z^{[1]})$
   - $\dots$ 依此類推，直到輸出預測值 $A^{[L]}$。
   - *註：此處應使用向量化實現，一次處理 $1000$ 個樣本，而非使用 `for` 迴圈。*

3. **計算損失與成本 (Cost Function)**：
   - 計算該 mini-batch 的成本 $J^{\{t\}}$：
     $$J^{\{t\}} = rac{1}{1000} \sum_{i=1}^{1000} \mathcal{L}(\hat{y}^{(i)}, y^{(i)}) + 	ext{正規化項 (Regularization term)}$$
   - *註：此處的損失與正規化計算僅針對當前 mini-batch $X^{\{t\}}, Y^{\{t\}}$ 中的樣本。*

4. **反向傳播 (Backpropagation) 與參數更新**：
   - 利用 $X^{\{t\}}$ 和 $Y^{\{t\}}$ 計算相對於 $J^{\{t\}}$ 的梯度。
   - 更新權重與偏置：
     $$W^{[l]} \leftarrow W^{[l]} -  lpha \, dW^{[l]}$$
     $$b^{[l]} \leftarrow b^{[l]} -  lpha \, db^{[l]}$$

## 4. 關鍵觀念：Epoch vs. Step

- **Epoch（世代 / 輪次）**：指的是**完整遍歷一次整個訓練集**（也就是遍歷完所有的 mini-batches）的過程。
- **效率與步數對比**：
  - **Batch 梯度下降法**：遍歷一次訓練集（1 Epoch），只能讓參數更新往前走 **1 步 (Step)**。
  - **Mini-Batch 梯度下降法**：同樣遍歷一次訓練集（1 Epoch），因為有 $5000$ 個 mini-batches，所以可以進行 **5000 次參數更新 (Steps)**。
- **多輪訓練**：為了使模型收斂，通常需要使用另一個外層迴圈（如 `for` 或 `while` 迴圈）來進行多個 Epoch 的訓練，直到模型收斂為止。

## 5. 三種梯度下降法規模之比較

| 類型 | Mini-Batch 大小 ($	ext{size}$) | 特性與優點 | 缺點與限制 |
| :--- | :--- | :--- | :--- |
| **Batch Gradient Descent**<br>(批次梯度下降) | $	ext{size} = M$<br>($M$ 為訓練集總數) | 每次迭代都處理整個訓練集。<br>優化路徑雜訊極低、步長相對大，能直接朝向極小值前進。 | 每次迭代都需要耗費大量時間處理龐大的訓練集，在大型訓練集上效率極低。 |
| **Stochastic Gradient Descent (SGD)**<br>(隨機梯度下降) | $	ext{size} = 1$ | 每個訓練樣本獨立為一個 mini-batch，一次只處理一個樣本。<br>能非常快速地開始取得進展，且無須等待。 | 1. **極度嘈雜**：前進方向雖然大體正確，但經常走錯方向。<br>2. **無法完全收斂**：會在極小值附近區域不斷震盪與徘徊。<br>3. **失去向量化優勢**：一次只處理一個樣本，計算效率極低。 |
| **Mini-Batch Gradient Descent**<br>(迷你批次梯度下降) | $1 < 	ext{size} < M$ | 介於兩個極端之間，在實務上**學習速度最快、效果最好**。<br>1. **保留向量化加速**：能一次處理多個樣本（如 1000 個）進行向量化計算。<br>2. **無須等待**：不用處理完整個訓練集即可更新參數並取得進展。 | 雖然前進方向比 SGD 更一致，但仍無法保證每次都朝向極小值，最終也無法完全收斂，而是在微小區域內震盪（可透過**緩慢降低學習率**來解決）。 |

## 6. 成本函數 $J$ 的震盪特性

- **Batch 梯度下降**：成本函數 $J$ 在每次迭代中都應該持續下降。如果出現上升，通常代表某些設定出錯（例如學習率過大）。
- **Mini-Batch 梯度下降**：成本函數 $J^{\{t\}}$ 因為每次迭代所計算的資料來自不同的 mini-batch ($X^{\{t\}}, Y^{\{t\}}$)，就像每次迭代都在不同的訓練集上訓練。因此，若將 $J^{\{t\}}$ 隨迭代次數畫出，其曲線會呈現**震盪與雜訊**，但整體趨勢仍應向下。
- **震盪原因**：有些 mini-batch（如第一個 $X^{\{1\}}, Y^{\{1\}}$）可能恰好比較簡單，使成本較低；有些（如第二個 $X^{\{2\}}, Y^{\{2\}}$）可能比較困難，或含有標記錯誤的樣本，導致成本上升。

## 7. 實務上選擇 Mini-Batch 大小的指南

1. **小規模訓練集（$M < 2000$）**：
   - 直接使用 **Batch Gradient Descent**（即 $	ext{size} = M$）。因為小資料集處理速度很快，不需使用 Mini-Batch。
2. **大規模訓練集（$M \ge 2000$）**：
   - 典型的 Mini-Batch 大小通常設定在 **64 到 512** 之間。
3. **2 的冪次方原則（Power of 2 Rule）**：
   - 由於電腦記憶體配置與存取設計，將大小設定為 **2 的冪次方**（例如 $64, 128, 256, 512$，有時可達 $1024$）能讓程式碼運行得更快。
4. **注意硬體記憶體限制**：
   - 必須確保一個 Mini-Batch 內的所有資料 ($X^{\{t\}}, Y^{\{t\}}$) 能**完全放入 CPU/GPU 記憶體**中。
   - 一旦資料量超出硬體記憶體限制，運算效能將會急劇下滑（掉落懸崖）。
5. **作為超參數進行搜尋**：
   - Mini-Batch 大小本質上是一個超參數。在實際操作中，建議嘗試幾種不同的 2 的冪次方數值，搜尋並選擇能最有效率降低成本函數 $J$ 的那一個大小。
