# 單一實數評估指標 (Single Number Evaluation Metric) 課堂筆記

## 為什麼需要「單一數字評估指標」？

* **加速開發迭代**：機器學習是一個高度經驗導向的循環過程（**想法 → 寫成程式碼 → 實驗測試 → 根據結果改進**）。在調整超參數或嘗試不同點子時，若能有一個單一的實數評估指標，就能讓你迅速判斷新嘗試的方法是變好還是變壞，進而大幅加快迭代與改善演算法的速度。
* **避免多重指標的抉擇困境**：如果同時看多個指標，當不同演算法互有優劣時，團隊很難在短時間內快速決定哪一個是「最好的」並繼續往下開發。

---

## 實務案例一：結合精確率 (Precision) 與召回率 (Recall)

在評估貓咪分類器時，我們通常會關注以下兩個常有權衡（Trade-off）關係的指標：

* **精確率 (Precision)**：在所有被分類器預測為「貓」的樣本中，實際真的是貓的比例。  
  * *例如*：精確率 95% 代表分類器判定是貓時，有 95% 的機率真的是貓。
* **召回率 (Recall)**：在所有實際是貓的圖片中，被分類器正確識別出來的比例。  
  * *例如*：召回率 90% 代表開發集（Dev Set）中所有實際是貓的圖片，分類器成功抓出了其中的 90%。

### ✕ 問題
若分類器 A 的召回率較佳，而分類器 B 的精確率較佳，我們很難直接判定誰比較好。

### ✓ 解決方案（F1 分數）
在機器學習文獻中，標準的做法是使用 **F1 分數 (F1 Score)** 來結合這兩者。F1 分數在數學上是精確率與召回率的**調和平均數 (Harmonic Mean)**，公式為：

$$\text{F1 Score} = \frac{2}{\frac{1}{\text{Precision}} + \frac{1}{\text{Recall}}} = 2 \times \frac{\text{Precision} \times \text{Recall}}{\text{Precision} + \text{Recall}}$$

透過這個指標，我們就能快速比較並選出表現較佳的模型（例如直接選擇 F1 分數較高的分類器 A）。

## 實務案例二：多地區市場的錯誤率

假設你正在為四個主要地理區域（美國、中國、印度、世界其他地區）開發貓咪 App，兩個不同的演算法在各個地區的錯誤率表現各有高低。

### ✕ 問題
同時追蹤、比較多個地區的 4 個錯誤率數字，會讓人難以迅速判定哪一個演算法更為優越。

### ✓ 解決方案（計算平均值）
除了持續追蹤各市場的表現外，建議**計算平均錯誤率**。只要平均表現是一個合理的單一評估指標，你就能透過這個單一數字（如選擇平均錯誤率最低的模型）快速做出決策，並以此為基礎繼續進行演算法的迭代優化。

---

## 關鍵總結

在啟動機器學習專案時，設定一個定義明確的**開發集 (Dev Set)**，並搭配一個**單一數字評估指標**，是提升團隊決策效率與演算法改進速度的核心關鍵。

# 機器學習專案評估指標筆記：最佳化指標與滿足型指標

在開發機器學習系統時，往往很難將所有在意的因素融合成單一的實數評估指標（Single Real Number Evaluation Metric）。此時，將指標區分為**最佳化指標（Optimizing Metric）**與**滿足型指標（Satisficing Metric）**，是相當實用且明確的折衷決策方法。

## 1. 核心定義與運作機制

* **最佳化指標（Optimizing Metric）**：
  * 這是你想要**盡可能極大化（或極小化）**的指標。
  * 在所有評估指標中，通常只會選擇一個作為最佳化指標，用來追求極致的表現。
* **滿足型指標（Satisficing Metric）**：
  * 這類指標不需要追求完美，只需要**「夠好」且達到設定的門檻（Threshold）**即可。
  * 一旦達到設定的門檻，你就不再介意它能超越多少（因為更進一步的提升對使用者來說可能沒什麼差別）。
* **多指標通則（General Rule for N Metrics）**：
  * 如果你同時在意 $N$ 個指標，合理的做法是挑選其中 **1 個指標作為最佳化指標**，其餘的 **$N-1$ 個指標全部設為滿足型指標**。

---

## 2. 實際應用案例

### 案例 A：貓咪分類器 (Cat Classifier)
* **情境**：你同時在意分類準確度（如 Accuracy 或 F1 Score）與運行時間（Running Time，即分類一張圖片需要幾毫秒）。
* **指標設定**：
  * **最佳化指標**：準確度（極大化）。
  * **滿足型指標**：運行時間，門檻設定為 $\le 100$ 毫秒。
* **決策方式**：在所有運行時間小於或等於 100 毫秒的分類器候選者中，選擇準確度最高的那一個。這樣可以避免用人工且不自然的公式去強行融合兩個不同性質的指標。

### 案例 B：喚醒詞／語音觸發系統 (Wake Word / Trigger Word Detection)
* **情境**：用於智慧音箱等語音控制設備（例如：Amazon Alexa、Google OK Google、Apple Hey Siri、百度你好百度）。你同時在意喚醒準確度與誤報率（False Positives，即無人說話時設備隨機喚醒的次數）。
* **指標設定**：
  * **最佳化指標**：喚醒準確度（極大化）。
  * **滿足型指標**：誤報次數，門檻設定為每運作 24 小時最多發生 1 次誤報。
* **決策方式**：在滿足「平均每天誤報不超過 1 次」的前提下，挑選喚醒準確度最高的系統。

---

## 3. 評估與計算對象

這些設定好的評估指標（最佳化與滿足型指標），必須在**訓練集（Training Set）**、**開發集（Development/Dev Set）**或**測試集（Test Set）**上進行評估與計算，這能讓專案團隊擁有幾乎自動化的方式，快速比較多個不同的分類器並挑選出最適合的版本。
